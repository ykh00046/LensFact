# LensFact Real-Data Pilot

This directory contains a no-build static pilot for LensFact using verified public data for twenty transparent spherical contact-lens products distributed in Korea.

## Structure

This directory is the web root. Every internal link is relative, so the site works from any root path.

The header nav is the same six links on all 48 pages, in both the desktop and the mobile copy: 포장 숫자 해석 (`decoder/index.html`), 제품, 검색, 공식 사양 비교, 렌즈 상식, 소개. Each page whose section has a nav entry marks it with `aria-current="page"` — two copies, desktop and mobile; the policy pages carry one, because they appear in the mobile nav only. The home page and the ten `terms/` pages mark none: home because the brand anchor — not a nav item — is the link home, the terms pages because the nav has no 용어 entry. Below 900px the desktop nav is hidden and the menu button needs JavaScript, so every page's `<head>` also carries a `<noscript><style>` block that hides the dead toggle and lays the mobile nav out in flow.

The home page is a router: it names the three things the site does and sends the reader to one of them. Three reading flows then tie the pages together. A reader holding a package opens `decoder/index.html` from the first card, types the figures printed on the blister and reads each figure's meaning plus the products that print the same value. A reader who searched for one word instead lands on `terms/<field>.html`, reads what the figure means, and follows a value row into `products/index.html?<field>=<value>`, which shows only the products printing that value and lists the condition as a removable chip. A reader who came for one product searches from the home page's second card or the header's 검색 link into `products/index.html#product-search`, opens `products/<slug>.html`, and reads each value with its source. From that product page the 이 제품과 비교하기 button opens `compare/index.html?p=<slug>` with the product as the first column, more products are added in the picker, and every row header in the table leads back to the term page for that figure. A reader who searched for one product against another lands on `compare/<id-a>-vs-<id-b>.html` instead: a static page for that one pair, which sorts the two products’ official figures into what can and cannot be placed in the same table, links back into the tool with both products preselected, and sends the reader on to either product page.

- `index.html`: home page, and nothing but a router. A hero (h1 + one lead sentence carrying `[data-product-count]`, filled from `products.js` at runtime so it cannot drift from the data) over three cards — 포장 숫자 해석 -> `decoder/index.html`, 제품 찾기 -> `products/index.html#product-search`, 제품 비교 -> `compare/index.html`. Each card is a static heading link, never a button, and the card itself is not wrapped in a link. Below the cards sits one trust sentence marked `[data-evidence-summary]`, so its 미확인 count is refreshed from `products.js` and its static fallback is checked against the computed value in the tests; it keeps the 최종 피팅은 전문가에게 확인하세요 clause. Nothing else is above the shared footer: the spec-input form moved to `decoder/index.html`, the twenty-button preset decoder was removed outright, and the three evidence example cards moved to `products/index.html`. An inline `WebSite` JSON-LD block carries the site name and description; it declares no `SearchAction`, because the product search has no results URL scheme to point at.
- `decoder/index.html`: the 포장 숫자 해석 page. It carries the `#input-decoder` form (BC, DIA, 함수율, Dk/t, 재질명, 교체주기 — all optional, at least one required): the reader types the figures printed on their own package and gets each figure's meaning plus a factual placement statement against `products.js` and a `표기 일치` product list. Values are computed in the page only: nothing is stored and nothing is sent. Every control and the result panel ship `disabled` / `hidden` and are enabled by `initInputDecoder()`, so with JavaScript off no reader can press a button that would only reload the page and discard what they typed. The form declares `data-product-base="../products/"` so the match links resolve from this depth; the attribute defaults to `./products/` when absent. `INPUT_FIELDS` covers six of the nine fields, so a visible 표기 뜻 전체 보기 block links all nine `terms/<field>.html` pages and marks the three that have no input box, and a `<noscript>` block states that the form needs JavaScript and repeats those links plus `products/index.html`.
- `products/index.html`: under the hero and above the grid sits the three-card `[data-evidence-examples]` section (moved off the home page on 2026-08-29; the attribute is the anchor `tests/static-content.test.js` locates it by), which shows three products whose official sources disagree and links each to its `./<slug>.html` page. The list itself is twenty static product cards written into the page markup; `initProductIndex()` reads those cards and only shows and hides them — it renders none of them from `products.js`. Besides the search box and the 제조사/교체주기 selects, the list accepts spec deep links `?bc= ?dia= ?water= ?dkt= ?material= ?replacement=` (exact value match through the shared parser: a conflicted field matches either recorded value, an unknown field never matches) and `?q=` to prefill the search. Active spec conditions appear as removable chips above the grid and are mirrored in `history.replaceState`. The header's 검색 link and the home page's second router card both point at `#product-search`. That id sits on the list `<section>`, not on the search input, because the filter wrapper ships `hidden` and a `display: none` element cannot be scrolled to; a reader without JavaScript therefore still lands on the product list, and with JavaScript `initProductIndex()` moves focus into the search box once the controls are enabled.
- `products/<slug>.html`: one page per product (`acuvue-oasys-1-day`, `dailies-total1`, `biofinity`, `acuvue-moist-1-day`, `myday`, `clariti-1-day`, `acuvue-oasys-2-week`, `precision1`, `biotrue-oneday`, `acuvue-oasys-max-1-day`, `dailies-aquacomfort-plus`, `acuvue-vita`, `total30`, `airoptix-plus-hydraglyde`, `proclear-1-day`, `biofinity-energys`, `ultra-one-day`, `miru-1day`, `soflens-daily`, `clalen-1day`). Thin HTML shell plus `<main data-product-page="<id>">`; `initProductPage()` renders every field with its full source list open, and a `<noscript>` table carries all values and the first source per field for crawlers and no-JS readers. Each page's comparison card carries a 이 제품과 비교하기 button linking `compare/index.html?p=<slug>`, which opens the comparison with that product as its only column.
- `knowledge/index.html`: content hub with one completed article and seven clearly marked pending topics.
- `knowledge/water-content-moisture.html`: evidence-based article about water content and perceived moisture.
- `terms/index.html`: list of the nine field terms, rendered from `fields.js` with each term's value count.
- `terms/<field>.html`: one page per field (`bc`, `dia`, `water`, `material`, `dkt`, `thickness`, `replacement`, `permit`, `uv`). Thin HTML shell plus `<main data-term-page="<id>">`; `initTermPage()` renders the meaning and caution from `fields.js` and a value-distribution table from `products.js` — one row per printed value with the products printing it, conflicted products appearing under each of their recorded values with their full printed string, and unknown ones grouped as 확인되지 않음. Rows for the six deep-linkable fields carry a `이 값으로 목록 보기` link into `products/index.html?<field>=<value>`. The `permit` page explains the 수허/제허 prefixes and MFDS lookup, the `uv` page separates 등급 표기, 차단율 and 투과율. A `<noscript>` copy of the same table is generated from the same `app.js` function, so the two cannot drift.
- `compare/index.html`: accessible official-spec comparison rendered from `assets/data/products.js`. A checkbox picker (`fieldset` "비교할 제품 선택") chooses up to 4 products (default: the first 3); the selection persists in the URL query `?p=<id>,<id>` so a comparison is linkable (a single id arriving from a product page renders one column and the picker hint asks for more), every row header links to that field's `terms/<field>.html` page in both the live and the `<noscript>` table, and `<noscript>` keeps the full all-product table and evidence list.
- `compare/<id-a>-vs-<id-b>.html`: one static page per recorded product pair (`acuvue-oasys-1-day-vs-dailies-total1.html`, `acuvue-oasys-1-day-vs-acuvue-moist-1-day.html`, `myday-vs-clariti-1-day.html`, `dailies-total1-vs-dailies-aquacomfort-plus.html`, `biofinity-vs-airoptix-plus-hydraglyde.html`, `acuvue-oasys-1-day-vs-acuvue-oasys-max-1-day.html`, `acuvue-oasys-1-day-vs-acuvue-oasys-2-week.html`, `dailies-total1-vs-total30.html`). Thin HTML shell plus `<main data-compare-pair="<id-a>,<id-b>">`; `initComparePairPage()` renders the whole body from `products.js` through `pairBodyMarkup()`, and the committed `<noscript>` copy is the output of the same function with the `ns-` id prefix. The file is generated by `tools/build-pair-pages.js` — run it after any product data change and never hand-edit a pair page; `tests/static-content.test.js` fails when a committed file differs from the generator. The pages answer which of the two products' official figures can be placed in one table and which cannot, with the reason derived from that pair's own states, conflicts and printed measurement conditions; they carry no recommendation, ranking or score. The pair order in a file name follows `COMPARE_COLUMNS`, so one pair has exactly one URL. Each page links into `compare/index.html?p=<id-a>,<id-b>`, into both product pages, and into the other pair pages its two products appear in; `compare/index.html` lists every pair page and, when the picker selection equals a pair, points at that page through `[data-compare-pair-link]`.
- `about/index.html`: what the site does and does not do, its independence statement, and contact.
- `policy/editorial.html`: editorial policy, evidence states, medical boundary, correction procedure.
- `policy/methodology.html`: source hierarchy, meaning of `raw`/`condition`/`verifiedAt`, why values are not merged.
- `policy/privacy.html`: privacy policy for the current no-cookie, no-analytics, no-ads site.
- `robots.txt`, `sitemap.xml`: discovery files. Both still contain the `DOMAIN-TBD` placeholder origin.
- `assets/css/style.css`: shared responsive stylesheet.
- `assets/fonts/pretendard/`: self-hosted Pretendard Variable (SIL OFL 1.1). `pretendard-dynamic-subset.css` declares 92 `@font-face` rules for the family `Pretendard Variable`, each with its own `unicode-range` and `font-display: swap`, pointing at the woff2 slices in `woff2-dynamic-subset/`. Every page links this stylesheet immediately before `assets/css/style.css`. The browser downloads only the slices a page's characters actually need, so a Korean page fetches a few tens of KB rather than the whole 2.9 MB set. `LICENSE.txt` is the upstream OFL text.
- `assets/js/app.js`: vanilla JavaScript for the menu, the input decoder on `decoder/index.html`, source details, filters, the comparison table, the product list and product pages, the term pages, and disabled ad slots.
- `assets/data/products.js`: repository-owned verified product values, evidence states, and official source URLs, plus each product's `slug` and `aliases` (Korean sales name, English global name, material name, and the US sales name where it differs from the Korean one).
- `assets/data/fields.js`: common field terminology used across all products.
- `assets/data/articles.js`: content status and metadata. `status: "term"` marks a hub topic that a term page already answers (BC and DIA); it renders as a linked card instead of 준비 중.

## Pre-publish checklist

The site currently ships with a placeholder origin and a preview-only `robots.txt`. Work through this list before making the site public.

1. **Replace `DOMAIN-TBD` with the real origin.** List every file that still contains it:

   ```bash
   grep -rIl DOMAIN-TBD site/ | wc -l
   ```

   Expected: 51 files total — 48 HTML pages, plus this README, `robots.txt`, and `sitemap.xml`. Use `grep -rIl DOMAIN-TBD site/` without `wc -l` when you need to inspect the command-derived path list.
2. **Contact email** — done 2026-08-28: `about/index.html` shows `interojo679@gmail.com` as a mailto link.
3. **Flip `robots.txt`.** Change `Disallow: /` to `Allow: /` and uncomment the `Sitemap:` line once the domain is final and the content is ready to be indexed.
4. **Register the site with search engines by meta tag only.** Google Search Console and Naver Search Advisor both allow verification through an HTML meta tag; use that method. Do not add a verification script — the site loads no external scripts, and that constraint stays.
5. **Verify 390px on a real device.** Check the header menu (open, Escape, click outside), the comparison table's horizontal scroll region, and that no page scrolls horizontally. The product pages and `decoder/index.html` must be checked too — the decoder is the only form on the site, and its `.decoder-layout` two-column grid and its `.input-grid` field grid both collapse at 390px. On the home page, check that the h1, the lead, the three router cards and the trust line all fit inside one 844px-tall viewport without scrolling; the `@media (max-width: 480px)` `.router-main` block in `style.css` is what buys the room.
6. **Re-check the product pages against `products.js`.** Every value, condition, source URL and `verifiedAt` on `products/<slug>.html` comes from `products.js`; the `<noscript>` fallback is a static copy, so re-generate or re-read it whenever product data changes. The pair pages under `compare/` are fully generated: run `node tools/build-pair-pages.js` after any product data change and never hand-edit one (`node tools/build-pair-pages.js --check` reports drift, and `tests/static-content.test.js` fails on it).
7. **Re-check `verifiedAt` dates.** If a source has changed since the last check, follow the correction procedure in `policy/editorial.html` before publishing.

## Data and Source Scope

The pilot covers ACUVUE OASYS 1-Day, DAILIES TOTAL1, Biofinity, 1-DAY ACUVUE MOIST, MyDay, clariti 1 day, ACUVUE OASYS 2-Week, PRECISION1, Biotrue ONEday, ACUVUE OASYS MAX 1-Day, DAILIES AquaComfort Plus, ACUVUE VITA, TOTAL30, AIR OPTIX plus HydraGlyde, Proclear 1 day, Biofinity Energys, Bausch + Lomb ULTRA ONE DAY (US name INFUSE One-Day), Miru 1day Menicon Flat Pack, SofLens daily disposable, and 클라렌 오투오투 원데이 그랩수 플러스 transparent spherical products. Korean official product pages, Korean IFUs, CooperVision Korea's 2023 specification sheet, CooperVision's global product reference guide, Alcon's US and international professional specifications, Alcon's and Bausch + Lomb's package inserts and fitting guides, Menicon Korea's consumer and professional product pages with Menicon's English instructions for use, and the MFDS UDI lookup are used to identify Korean distribution and permit information. DAILIES AquaComfort Plus and AIR OPTIX plus HydraGlyde are the two products with no Korean official page at all; their Korean distribution is identified from the MFDS UDI ledger alone. Manufacturer technical or professional specifications supply BC, DIA, water-content, Dk/t, and thickness values. 클라렌 오투오투 원데이 그랩수 플러스 is the first domestically manufactured product on file: its permit number carries the 제허 (manufacturing) prefix rather than 수허 (import), so the comparison and summary row label is now `한국 허가번호` with a `수허(수입)·제허(제조)` note. Scientific literature supports the water-content article.

Source links are ordinary user-initiated external links. The pages load no external scripts, styles, images, analytics, advertising, APIs, or CDNs at runtime; the web font is served from this site's own origin alongside the pages, never from a font CDN. `ADS_ENABLED=false` remains fixed and all ad-slot elements stay hidden.

- Biofinity's and MyDay's centre thickness are `unknown`: no reviewed official source states the value. Dk/t depends on thickness, so both Dk/t figures are read without that condition.
- Two corrections were applied on 2026-08-28 and logged in `docs/verification/CORRECTIONS.md`: Biofinity's centre thickness `0.08 mm` was withdrawn for lack of a reproducible source, and CooperVision Korea's legal name was fixed from `쿠퍼비젼코리아(주)` to `쿠퍼비전코리아(주)`.
