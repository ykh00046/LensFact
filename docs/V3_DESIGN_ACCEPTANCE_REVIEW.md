# LensFact V3 디자인 수용 검토

## 결론

**V3를 LensFact 홈페이지 디자인 방향으로 수용할 것을 권고한다.**

Claude Design을 한 번 더 돌리기보다, 아래 남은 보완 사항을 Codex의 실제 정적 프로토타입 구현 조건으로 넘기는 편이 효율적이다.

## 확인한 내용

- `LensFact Home V3.dc.html`을 로컬 HTTP 서버로 실행했다.
- 데스크톱 1280 및 모바일 390 화면을 실제 브라우저에서 확인했다.
- 데스크톱·모바일 전환, BC 상세 열기, 출처 펼치기, 모바일 메뉴 존재를 확인했다.
- 런타임 오류 표시는 0건이었다.
- 모바일에서 긴 한국어 문구와 포장 라벨 값은 현재 주요 화면에서 깨지거나 잘리지 않았다.
- V2의 내부 검수 도구 같은 밀도가 줄었고, 첫 화면에서 서비스 목적과 주 행동이 명확해졌다.
- Coral `#F48067`, Midnight Blue `#051230`, White, Soft Ivory, Pale Blue 사용이 과하지 않다.
- 상세 출처와 과학적 제한이 사용자 행동 뒤로 이동해 progressive disclosure가 작동한다.

## Codex 독립 검토와의 차이

Codex는 `REVISE ONCE`를 제시했다. 주요 이유는 다음 두 가지였다.

1. 안전 경계 문구가 푸터에만 있다.
2. Codex 환경에서는 브라우저 권한 문제로 모바일 실측 검증을 하지 못했다.

2번은 Hermes가 실제 390 화면을 브라우저로 확인해 해소했다. 1번은 레이아웃 방향을 다시 설계할 문제라기보다 실제 구현 카피의 작은 수정이므로, Claude Design의 네 번째 반복 없이 Codex 구현 조건으로 처리한다.

## Codex 구현 시 필수 보완

1. Hero 직후 신뢰 문장 중 하나를 다음 안전 경계로 교체하거나 추가한다.
   - `최종 적합성·도수·피팅은 전문가에게 확인합니다.`
2. `2026.08.27 확인`, `example.invalid`, 예시 제조사·문서를 실제 데이터로 이식하지 않는다.
3. `x-dc`, `sc-for`, `support.js`, 고정 1280/390 프레임, 인라인 스타일, CDN 런타임을 생산 코드로 가져오지 않는다.
4. 모바일 메뉴와 아이콘형 컨트롤에 `aria-label`, `aria-expanded`, 키보드 포커스를 구현한다.
5. 실제 정적 데이터 스키마에는 값별 출처, 확인일, 측정 조건, 충돌 상태를 분리해 둔다.
6. 모든 화면에서 추천·순위·적합 점수·구매 유도 표현을 사용하지 않는다.

## 디자인 슬롭 진단

점수: **1/10**

- 감지 항목: 신뢰 문장 3개가 동일 가중치의 짧은 열로 배치된 점이 약한 feature-tile 패턴에 가깝다.
- 다만 아이콘 카드, 그라데이션, 유리 효과, 거대 통계, 중앙 정렬 일변도, 잘못된 surface는 없다.
- 홈페이지가 Decide/Learn surface라는 목적과 Hero 구성이 일치하므로 방향 변경 사유는 아니다.
