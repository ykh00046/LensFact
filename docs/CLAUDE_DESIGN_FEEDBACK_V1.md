# LensFact Claude Design 피드백 V1

아래 내용을 기존 LensFact 콘셉트 보드에 대한 수정 요청으로 전달해 주세요.

---

세 안 모두 방향성이 분명하고, 흔한 AI 랜딩페이지 문법을 피한 점은 좋습니다. 이제 세 안 중 하나를 고르는 대신 **A를 MVP의 주 화면으로 확정하고, B와 C의 강점을 필요한 위치에 통합한 단일 V2 방향**으로 정리해 주세요.

## 1. 방향 확정

- 주 화면: **Concept A — Package Decoder**
- 별도 2차 화면: **Concept B — Evidence Desk의 공식 사양 비교**
- 문맥 도움말·콘텐츠: **Concept C — Material Atlas의 소재 설명**

첫 방문자가 5초 안에 “렌즈 포장 숫자를 해석하는 서비스”라고 이해해야 하므로 A가 홈에 가장 적합합니다. B는 신뢰를 만드는 비교·출처 레이어로, C는 BC·함수율·Dk/Dk/t를 설명하는 보조 콘텐츠로 사용해 주세요.

## 2. V2에서 보여줄 화면

다음 네 화면을 데스크톱과 모바일 흐름이 이해되도록 보여 주세요.

1. Package Decoder 기본 상태
2. 한 사양을 선택한 상세 상태 — 해설, 값 상태, 실제 출처 정보 영역 포함
3. 두 제품 공식 사양 비교 화면
4. 모바일 비교 화면 — 현재 2열 축소표가 아닌 세로형 비교 패턴

새로운 범용 랜딩페이지를 만들지 마세요. A의 포장 레이블 중심 구성을 유지해 주세요.

## 3. 모바일 비교 재설계

현재 390px의 2열 비교는 긴 한국어 제품명, 출처명, 충돌 주석이 들어오면 너무 작고 쉽게 잘립니다.

다음 중 하나를 사용해 세로로 읽히게 해 주세요.

- 항목 하나 아래에 제품 A와 B 값을 세로 배치
- 제품 A/B 전환 탭 + 차이 요약
- 항목별 접힘 상세

가로 스와이프 표는 피하고, 페이지는 고정 `844px + overflow:hidden`이 아니라 자연스럽게 세로 스크롤되어야 합니다. 본문은 모바일에서 대체로 14px 이상, 출처·상태 텍스트도 12px 미만으로 지나치게 작아지지 않게 해 주세요.

## 4. 값 상태 컴포넌트 구체화

각 사양값에 다음 상태를 색상뿐 아니라 텍스트 레이블과 형태로 구분해 주세요.

- 공식 출처에서 확인
- 확인되지 않음
- 출처 간 충돌
- 측정 조건 미공개
- 렌즈팩트 편집 해설

색각에 관계없이 상태를 식별할 수 있어야 합니다. 클릭 가능한 사양 행은 실제 구현에서 `div onClick`이 아니라 키보드로 조작 가능한 `button` 또는 적절한 컨트롤로 만들 것을 전제로 디자인해 주세요. 명확한 포커스 상태도 보여 주세요.

## 5. 출처 영역 확장

현재의 `식약처 허가정보` 또는 `제조사 공식 사양` 칩은 방향은 좋지만 실제 검증 정보를 담기에는 부족합니다. 상세 상태에 아래 항목이 들어갈 자리를 만들어 주세요.

- 출처 유형
- 출처 기관·제조사
- 문서명 또는 페이지 제목
- 원문 표기
- 출처 링크
- 확인일
- 값이 충돌할 경우 출처별 값

`2026.08.27 확인`은 프로토타입 예시일 뿐 실제 검증일로 보이지 않게 `예시 확인일`로 표시해 주세요.

## 6. 과학적 표현 수정

- **Dk와 Dk/t를 분리**하고 원문 metric type을 명확히 표시해 주세요.
- Dk/t는 제조사 원문 표기, 단위, 시험 도수·두께 기준·측정 조건이 확인되지 않으면 `직접 비교 제한` 상태로 보여 주세요. 단위를 임의로 통일하거나 빈칸으로 두지 마세요.
- 함수율은 가능한 경우 core/bulk/surface 여부를 보여줄 수 있는 구조를 마련해 주세요.
- UV는 `있음` 대신 `공식 UV 표기 확인`처럼 표현하고, 차단율·조건이 없으면 이를 별도로 미확인 처리해 주세요. 선글라스를 대체한다는 인상을 주면 안 됩니다.
- 교체주기 `1일`은 출처가 확인된 `제조사/포장 표기 교체 일정`으로 표현해 주세요. 식약처 데이터라고 임의 가정하지 마세요.
- Concept C의 소재별 함수율·Dk/t 범위 막대는 충분히 검증된 실제 데이터셋이 생기기 전까지 제거해 주세요. 소재군의 보편적 범위처럼 보일 위험이 있습니다.
- 소재 설명은 `일반 편집 해설`과 `개별 제품 공식 사실`을 시각적으로 분리해 주세요. 착용감·안전성·개인 적합성을 예측하는 문장으로 이어지면 안 됩니다.

## 7. 추천처럼 보이는 표현 제거

`선택한 조건과 일치하는 제품 12개`는 개인 적합성 추천처럼 읽힐 수 있고 숫자도 검증되지 않은 예시입니다.

다음처럼 중립적인 탐색 표현으로 바꿔 주세요.

- `선택한 공개 사양으로 필터링한 제품`
- `선택한 표기값을 포함한 제품`

`추천`, `나에게 맞는`, `베스트`, `순위`, `적합 점수`는 사용하지 마세요. 정렬이 필요하면 가나다순·브랜드순·최근 확인일순처럼 기준을 명시해 주세요.

## 8. 제품 식별 불확실성 표시

국내 판매명, 제조사명, 수입·판매원, 식약처 허가명, 영문명, 포장 표기가 항상 1:1로 대응하지 않습니다. 제품 상세에 다음 상태가 들어갈 공간을 마련해 주세요.

- 공식적으로 연결 확인
- 별칭으로 연결
- 동일 제품 여부 검토 중

잘못된 제품에 사양을 연결하는 것이 가장 큰 신뢰 리스크입니다.

## 9. 그대로 유지할 것

- A의 포장지 자체가 인터페이스가 되는 구성
- B의 값별 출처·확인일·미확인·충돌 표시
- C의 차분한 편집형 분위기와 소재 설명 방식
- 병원처럼 보이지 않는 문서형 톤
- 구매·예약·쿠폰·제휴 링크·제품 순위가 없는 구조
- `최종 적합성·도수·피팅은 안경사 또는 안과 전문인에게 확인하세요.` 경계 문구
- 44px 이상 터치 영역과 `prefers-reduced-motion`

## 10. 프로덕션 핸드오프 전제

현재 `.dc.html + support.js`는 시각 콘셉트 확인용으로만 사용합니다. 다음 구현 단계의 산출물은 이 런타임을 그대로 쓰지 않고 일반적인 접근 가능한 정적 웹 코드로 재구축할 예정입니다.

V2에서는 다음 반응형 규칙도 설명해 주세요.

- 360 / 390 / 768 / 1280px 이상
- 긴 제품명·출처명·원문값의 줄바꿈
- 상세 패널·하단 시트의 스크롤 소유권
- sticky header 동작
- unknown/conflict 주석이 길어졌을 때의 확장 방식

이번 수정도 디자인 단계입니다. DB, 인증, CMS, 분석, 광고, 외부 백엔드, 배포, 구매 기능은 만들지 마세요.
