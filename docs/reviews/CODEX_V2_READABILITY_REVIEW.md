# LensFact V2 가독성 리뷰

## 1. V2가 여전히 너무 조밀하고 낯선 이유

V2는 이전 피드백의 항목을 성실하게 반영했지만, 그 결과가 일반 소비자용 홈페이지가 아니라 디자인 검수용 대시보드처럼 보입니다. 첫 화면부터 화면 탭, 데스크톱/모바일 동시 프레임, 값 상태 범례, 출처 구조, 제품 식별 상태, 과학적 제한, 반응형 규칙이 한꺼번에 등장합니다. 정보의 정확성은 올라갔지만 방문자의 첫 과제인 “내 렌즈 포장지 숫자가 무슨 뜻인지 알기”는 뒤로 밀립니다.

일반적인 한국 소비자 정보 사이트는 처음에 하나의 질문과 하나의 행동을 줍니다. 반면 V2는 사용자가 서비스를 쓰기도 전에 “이 서비스가 데이터를 어떻게 검증하는지”를 먼저 학습하게 만듭니다. 10px-12px대 보조 텍스트와 모노스페이스 메타데이터도 많아 의료기기 문서, QA 명세, 내부 어드민 화면의 인상이 강합니다.

특히 홈 기본 상태에서 상태 범례 5종, 제품 식별 문구, 출처/확인일 언어, Dk/Dk/t 같은 과학 qualifier가 선노출되는 점이 문제입니다. 이 정보는 LensFact의 신뢰를 만드는 핵심이지만, 첫 화면의 주인공이 되면 소비자는 “어디부터 읽어야 하는지”를 잃습니다.

## 2. 권장하는 일반 소비자 사이트 구조

홈은 “렌즈 포장지 숫자를 쉽게 해석하는 곳”으로 시작해야 합니다. 상단에는 로고, 짧은 내비게이션, 검색/입력 진입점만 두고, 첫 섹션은 실제 포장지 라벨 이미지 또는 라벨형 UI와 “BC, DIA, 함수율 같은 숫자를 입력하거나 선택하세요”라는 단일 행동으로 구성합니다.

권장 홈 계층은 다음 순서가 적합합니다.

1. 첫 화면: 브랜드명, 한 문장 설명, 포장 숫자 입력/선택 CTA, 대표 패키지 라벨 시각.
2. 즉시 해석 영역: BC, DIA, 재질, 함수율, Dk/t, 교체 일정, UV 표기 중 사용자가 고른 항목의 쉬운 설명.
3. 신뢰 요약: “공식 출처 기반”, “판매/추천 없음”, “미확인 값은 미확인으로 표시” 같은 3개 이하의 짧은 원칙.
4. 비교 진입: “공식 사양 비교하기” 카드 하나.
5. 학습 진입: “포장지 읽는 법”, “렌즈 상식 확인” 기사 링크.
6. 하단 경계 문구: 최종 적합성, 도수, 피팅은 안경사 또는 안과 전문인에게 확인.

별도 페이지 역할은 분리해야 합니다. 상세 페이지는 한 제품 또는 한 입력 결과의 값별 해석과 출처를 보여 줍니다. 비교 페이지는 두 제품 또는 여러 제품의 공식 사양을 비교하되, 모바일에서는 항목별 카드와 접힘 상세를 사용합니다. 기사 페이지는 Dk와 Dk/t 차이, 함수율 오해, 소재 설명, UV 표기 같은 개념을 읽을거리로 다룹니다. Evidence/Methodology 페이지는 검증 방법, 출처 유형, 충돌 처리, 제품 식별 불확실성을 설명하는 곳입니다.

## 3. 처음 보이는 정보와 숨길 정보

처음부터 보일 정보는 아주 적어야 합니다.

- LensFact 이름.
- “렌즈 포장지의 숫자를 출처와 함께 해석합니다.”
- 포장지 숫자 입력 또는 샘플 선택.
- 대표 사양 5-7개 이름: BC, DIA, 재질, 함수율, Dk/t, 교체 일정, UV 표기.
- 선택한 항목의 쉬운 한 줄 설명.
- “공식 출처 기반”, “추천/판매 없음”, “미확인 값 표시” 신뢰 원칙.
- 전문가 확인 경계 문구.

다음 정보는 초기 노출하지 말고 `자세히 보기`, `출처 보기`, `비교 제한 보기`, accordion 안으로 옮겨야 합니다.

- 출처 유형, 기관/제조사, 문서명, 원문 표기, URL, 확인일.
- 상태 범례 5종 전체 설명.
- 출처 간 충돌의 출처별 값 목록.
- Dk와 Dk/t의 측정 조건, 시험 도수, 중심 두께, 단위 qualifier.
- 함수율의 core/bulk/surface 기준 설명.
- 제품 식별 상태의 세부 근거.
- 반응형 규칙, 구현 전제, aria 관련 명세.
- 프로토타입 데이터 고지의 긴 문장.

초기 화면에서는 상태를 완전히 숨기라는 뜻이 아닙니다. 값 옆에는 “공식 확인”, “확인되지 않음”, “직접 비교 제한”처럼 짧은 칩만 보이고, 왜 그런지는 눌렀을 때 열리게 해야 합니다. 법적/과학적 정확성은 유지하되, 정보의 깊이를 사용자의 행동 이후로 늦추는 것이 핵심입니다.

## 4. 권장 팔레트와 접근성 사용 규칙

V3의 기본 팔레트는 영상 참고안 중 Coral `#F48067` + Midnight Blue `#051230`을 추천합니다. 소비자 사이트처럼 밝고 기억되는 인상을 만들면서도, Midnight Blue가 충분한 텍스트 대비를 제공합니다. 보조 배경은 White `#FFFFFF`, Soft Ivory `#FFF8F2`, Pale Blue `#EAF5FF`, Border Gray `#E5E7EB`, Muted Text `#5B6472` 정도로 정리합니다.

사용 규칙은 명확해야 합니다.

- 본문 텍스트와 주요 제목은 `#051230`을 사용합니다.
- 흰 배경 위 `#051230`은 대비가 충분하므로 기본 텍스트로 안전합니다.
- Coral `#F48067`은 CTA 배경, 선택 상태, 작은 강조 면에만 사용합니다.
- Coral 위에는 흰 본문 텍스트를 올리지 않습니다. 확인된 대비가 2.58:1이라 본문/버튼 텍스트에 부적합합니다.
- Coral 배경 위 텍스트가 필요하면 `#051230`을 사용합니다. 확인된 대비가 7.16:1입니다.
- Midnight Blue 배경 위 흰 텍스트는 짧은 큰 제목이나 내비게이션에 제한하고, 긴 본문은 흰 배경 또는 아이보리 배경 위 Midnight Blue로 둡니다.
- 상태 색은 팔레트 강조색과 분리합니다. 예를 들어 확인은 Midnight Blue, 미확인은 Gray, 충돌은 Amber/Brown, 직접 비교 제한은 Olive/Slate처럼 텍스트 레이블과 아이콘 형태를 함께 둡니다.

대체 팔레트로 Coffee Brown `#71502F` + Olive Green `#788860`도 가능하지만, 현재 V2의 문서형 갈색/베이지 인상을 더 강화할 위험이 있습니다. “평범한 소비자 웹사이트”라는 목표에는 Coral + Midnight Blue가 더 명료합니다. Ivory + Light Sky Blue는 부드럽지만, 의료/보험 안내 페이지처럼 밋밋해질 수 있어 보조 배경으로만 쓰는 편이 낫습니다.

## 5. Claude Design V3용 우선순위 revision brief

1. LensFact V3는 내부 명세 보드가 아니라 실제 한국 소비자 정보 사이트의 홈페이지처럼 다시 설계한다. 첫 화면에는 하나의 핵심 메시지와 하나의 주 행동만 둔다.

2. 홈의 첫 문장은 “렌즈 포장지의 숫자를 출처와 함께 해석합니다.”로 둔다. 그 아래 CTA는 “포장 숫자 입력하기” 또는 “샘플로 해석 보기”처럼 중립적으로 작성한다.

3. 첫 화면에서 출처 표, 상태 범례 전체, 과학 qualifier 전체, 충돌 세부값, 반응형 명세를 노출하지 않는다. 이 정보는 상세 페이지, accordion, `출처 보기`, `자세히 보기`로 이동한다.

4. 패키지 라벨형 시각은 유지하되 더 친숙하게 만든다. 실제 제품 패키지를 연상시키는 큰 라벨 또는 카드 하나를 중심에 두고, BC/DIA/함수율/Dk/t 같은 숫자는 탭 가능한 작은 주석으로 표시한다.

5. 선택 전 홈에는 대표 항목명과 쉬운 설명만 보인다. 선택 후에는 오른쪽 패널 또는 모바일 하단 시트에 “뜻”, “주의할 점”, “출처 요약”, “자세히 보기”가 순서대로 열린다.

6. 출처 정보는 처음에는 “제조사 공식 사양 · 예시 확인일”처럼 한 줄 요약만 보인다. 전체 출처 유형, 기관, 문서명, 원문 표기, 링크, 출처별 충돌값은 `출처 보기` 안에 둔다.

7. 비교 페이지는 별도 페이지로 분리한다. 홈에 비교표를 넣지 말고, 홈에는 “공식 사양 비교”로 이동하는 조용한 카드만 둔다.

8. 모바일 비교는 항목별 카드 구조로 유지하되, 각 카드의 기본 상태는 값과 짧은 상태만 보이고 출처/주석은 접는다. 긴 한국어 제품명과 출처명은 말줄임보다 자연 줄바꿈을 우선한다.

9. 기사/학습 페이지를 따로 둔다. Dk와 Dk/t, 함수율, 소재, UV 표기, 교체 일정 오해는 홈에서 모두 설명하지 말고 “포장지 읽는 법”과 “렌즈 상식 확인”에서 다룬다.

10. 팔레트는 Coral `#F48067` + Midnight Blue `#051230`을 기반으로 한다. Coral은 CTA와 선택 강조에 쓰되 흰 글자를 올리지 않는다. 기본 텍스트는 Midnight Blue, 배경은 White/Ivory, 정보 박스는 Pale Blue를 사용한다.

11. 상태 표시는 색만 쓰지 않는다. “공식 확인”, “확인되지 않음”, “출처 차이”, “직접 비교 제한”, “편집 해설”을 짧은 텍스트 칩과 아이콘 형태로 함께 표시한다.

12. `추천`, `베스트`, `순위`, `적합 점수`, `나에게 맞는` 표현은 쓰지 않는다. 비교/필터 언어는 “선택한 표기값을 포함한 제품”, “공개 사양 기준으로 보기”, “정렬 기준: 가나다순/브랜드순/최근 확인일순”처럼 쓴다.

13. 전문가 경계 문구는 짧고 반복 가능하게 만든다. “최종 적합성·도수·피팅은 안경사 또는 안과 전문인에게 확인하세요.”를 상세/비교/기사 하단에 일관되게 둔다.

14. V3 산출물은 390px 모바일 첫 화면과 1280px 데스크톱 첫 화면을 각각 실제 홈페이지처럼 보여 준다. 데스크톱/모바일을 한 캔버스 안에 동시에 축소 전시하지 않는다.

## 6. V2에서 가져오지 말아야 할 것

- 디자인 보드용 상단 탭 5개를 실제 사이트 구조처럼 가져오지 않는다.
- 데스크톱 1440 화면을 78% 축소한 프레임과 모바일 390 프레임을 한 화면에 동시에 놓는 방식을 가져오지 않는다.
- 홈 첫 화면에 값 상태 범례 5종 전체를 노출하지 않는다.
- 홈 첫 화면에 출처 정보 전체 표를 노출하지 않는다.
- 홈 첫 화면에 제품 식별 불확실성, 과학 표현 규칙, 반응형 규칙을 명세처럼 노출하지 않는다.
- 10px-11px 모노스페이스 메타데이터를 정보 구조의 주된 언어로 쓰지 않는다.
- 베이지/회색 문서형 배경과 얇은 선 중심의 내부 툴 같은 인상을 그대로 유지하지 않는다.
- “예시 확인일 2026.08.27”을 모든 화면 상단의 주요 정보처럼 반복하지 않는다.
- 비교표와 상세 출처 레이어를 홈의 기본 경험에 합치지 않는다.
- 과학적 제한 문구를 모두 첫 화면에 펼쳐 놓지 않는다.
- 구현 전제, aria 설명, 반응형 명세를 소비자 화면의 visible copy로 가져오지 않는다.
- V2의 정보량을 유지한 채 색상만 바꾸는 방향으로 가지 않는다. V3의 핵심은 장식 변경이 아니라 정보량과 페이지 역할의 재분배다.
