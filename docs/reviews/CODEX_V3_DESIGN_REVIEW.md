# LensFact V3 디자인 리뷰

## Verdict: REVISE ONCE

V3는 방향으로는 선택할 만합니다. V2의 가장 큰 문제였던 내부 검수 도구 같은 밀도와 낯선 구조를 상당히 줄였고, 첫 화면도 일반 소비자 정보 사이트에 가까워졌습니다. `내 렌즈 포장지, 숫자부터 읽어보세요.`라는 제목, `포장 숫자 해석하기` CTA, 포장 라벨형 예시는 5초 안에 “렌즈 포장지 숫자를 쉽게 읽는 사이트”라는 목적을 전달합니다.

다만 그대로 ACCEPT하기에는 한 번 더 다듬어야 합니다. 특히 “처방·적합성 판단을 하지 않는다”는 안전 경계가 첫 화면에서는 충분히 즉시 보이지 않습니다. MVP brief의 5초 기준에는 “설명은 하지만 처방하거나 판매하지 않는다”가 포함되므로, 현재처럼 전문가 확인 문구가 하단에만 있으면 방향 확정 전에 보완이 필요합니다.

## 평가

첫-5초 명확성은 좋습니다. 데스크톱 썸네일 기준으로 로고, 짧은 내비게이션, 큰 히어로 문장, CTA, 패키지 라벨 카드가 한눈에 들어오며 V2처럼 상태 범례나 출처 표가 먼저 보이지 않습니다. 소비자 사이트 친숙성도 개선됐습니다. 흰 배경, 넓은 여백, 3개 신뢰 문장, 자주 찾는 숫자 카드 구성은 일반 정보 사이트의 문법에 가깝습니다.

가독성과 정보 밀도는 데스크톱에서 대체로 적절합니다. 본문 16px 이상, 히어로 48px, 라벨 값 중심의 모노스페이스 제한은 V3 프롬프트와 맞습니다. 모바일 소스도 390px 기준 히어로 32px, 본문 15px 이상, 터치 영역 44px 이상을 대부분 지킵니다. 다만 이 환경에서는 Chrome/Edge headless가 crashpad 권한 오류로 실행되지 않아 모바일 실제 스크린샷은 확인하지 못했고, 모바일 평가는 소스 기반입니다.

Progressive disclosure는 V3의 가장 좋은 변화입니다. 기본 라벨에는 BC, DIA, 함수율만 보이고 재질, Dk, Dk/t, 교체, UV는 `포장지 표기 전체 보기` 뒤에 둡니다. 항목 선택 후에도 `뜻`, `주의할 점`, `출처 요약`, `출처 보기` 순서로 열리며, 긴 URL, 원문 표기, 측정 조건, 충돌값은 상세 영역에 숨겨져 있습니다. 이는 “전문성은 뒤에서 받치고 첫인상은 쉽고 밝게”라는 V3 목표와 잘 맞습니다.

색상은 지정 팔레트를 잘 따릅니다. 기본 텍스트 `#051230`, 보조 텍스트 `#5B6472`, 배경 `#FFFFFF`, `#FFF8F2`, `#EAF5FF`, 강조 `#F48067` 사용이 과하지 않습니다. 대비도 주요 조합은 안전합니다. `#051230` on white는 18.49:1, `#5B6472` on white는 5.98:1, `#8A4B12` on pale blue는 6.14:1입니다. Coral 위 흰 글자 금지 규칙도 현재 주요 UI에서는 위반하지 않습니다.

법적·안전 문구는 절반은 통과입니다. “제품을 판매하거나 순위를 매기지 않습니다”, “순위나 점수는 매기지 않습니다”, “독립 정보 서비스 · 판매하지 않습니다”는 좋습니다. 그러나 “최종 적합성·도수·피팅은 안경사 또는 안과 전문인에게 확인하세요.”가 푸터에만 있어 첫 화면의 안전 경계로는 약합니다.

구현 핸드오프 리스크는 명확히 분리해야 합니다. 현재 파일은 `x-dc`, `sc-for`, `support.js`, 인라인 스타일, 고정 1280/390 프레임, CDN React/Babel/font, `example.invalid`, 예시 확인일을 포함한 디자인 프로토타입입니다. 생산 구현에서는 이 구조를 그대로 가져오지 말고, 접근 가능한 실제 HTML/컴포넌트와 정적 데이터 스키마로 다시 만들어야 합니다.

## 남은 변경

1. 히어로 직후 신뢰 문장 3개 안에 안전 경계를 포함하세요. 예: `최종 적합성·도수·피팅은 전문가에게 확인합니다.` 판매/순위 없음과 함께 5초 안에 보여야 합니다.

2. 모바일 실제 화면을 390px에서 다시 확인하세요. 소스상 크기는 좋아 보이지만, 긴 한국어 문장과 라벨 값이 실제 브라우저에서 어색하게 줄바꿈되는지는 별도 캡처가 필요합니다.

3. 생산 핸드오프에서 미리보기 크롬, 고정 프레임, `x-dc/sc-for/support.js`, 인라인 스타일, CDN 런타임을 제외한다고 명시하세요. 이것은 디자인 방향이지 구현 골격이 아닙니다.

4. `2026.08.27 확인`, `example.invalid`, 예시 제조사/문서는 샘플 데이터임을 더 강하게 분리하세요. 실제 검증일이나 실제 출처처럼 이식되면 신뢰 리스크가 큽니다.

5. 모바일 메뉴 버튼과 아이콘형 컨트롤은 구현 명세에서 `aria-label`, `aria-expanded`, 키보드 포커스 상태를 요구하세요. 디자인 선택의 문제는 아니지만 핸드오프 누락 위험이 있습니다.

## 최종 판단

V3는 REJECT가 아닙니다. V2의 조밀함과 내부 도구 느낌을 벗어났고, LensFact의 홈 방향으로 삼을 수 있습니다. 단, 안전 경계를 첫 화면에 올리고 모바일 실측 검증 및 구현 핸드오프 분리를 한 번 더 반영한 뒤 방향을 확정하는 것이 맞습니다.
